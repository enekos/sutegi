# Sutegi calls

A Sutegi-only example: authenticated two-person signalling, native browser
WebRTC media, opt-in local camera recording, streaming upload and range playback.
No HRIS code, SDK, media server or new Cargo dependencies.

```sh
export CALL_TOKEN='replace-with-a-long-random-access-key'
cargo run -p call-example -- 127.0.0.1:8080
```

Open `http://127.0.0.1:8080` in **two separate browser profiles**. Enter the
same room and access key, then join and grant camera/microphone access. A
profile has one HttpOnly room session; reconnecting replaces its old socket.
Click **Record my camera**, then **Stop and save recording**. Playback below
supports seeking. Leaving stops camera/microphone tracks. Recordings contain
only the recorder's own tracks; this example does not mix remote media.

The server requires a key of at least 16 characters. Sessions expire after an
hour and are capped at 128; rooms hold at most two connections. This shared
key is demo authentication: replace `/session` with your app's identity and
room membership checks when integrating. Recording keys are generated by the
server and looked up only within the authenticated session's room.

## Deployment and TURN

Localhost works as a camera-enabled secure context. Other hosts need HTTPS
and WSS at your reverse proxy. Preserve `Host` and `Origin`; enable
`CALL_SECURE_COOKIE=1`. Configure proxy upload limits/timeouts to allow the
64 MiB recording route and WebSocket upgrades. The example binds the address
passed on the command line; the framework's default is `0.0.0.0:8080`.

- `CALL_TOKEN`: required shared room access key; never included in a URL.
- `CALL_DATA`: recording directory (default `data/call-recordings`). Use a
  persistent volume and implement retention/quotas for your deployment.
- `CALL_ICE_SERVERS`: JSON array of browser RTCIceServer entries, default `[]`.
- `CALL_RELAY_ONLY=1`: require a TURN relay, useful for a deployment smoke test.
- `CALL_SECURE_COOKIE=1`: add Secure to session cookies when serving over HTTPS.

Example ICE configuration (supply real, short-lived TURN credentials):

```sh
export CALL_ICE_SERVERS='[{"urls":["turn:turn.example.com:3478?transport=udp","turns:turn.example.com:5349?transport=tcp"],"username":"temporary-user","credential":"temporary-password"}]'
export CALL_RELAY_ONLY=1
```

An external TURN service relays media when direct connectivity is unavailable.
Sutegi relays SDP/ICE only. The server chooses the peer and attaches a
connection-pair generation; messages from an old pair are ignored. The client
serializes negotiation, retries signalling with bounded exponential backoff,
and rebuilds the peer connection after reconnect. SIGTERM makes readiness
fail immediately and closes existing calls/uploads at the five-second deadline.

Rooms, sessions and signalling are process-local. Run a single instance or
add shared membership/routing before multiple replicas. On restart, clients
must authenticate again. The example does not implement SFU mixing, PSTN,
transcription, AI voice processing, resumable uploads, or recording retention.
For object-storage deployments, use the signed URL flow in
[Streaming uploads](../../docs/UPLOADS.md).

## Reproducible browser verification

`verify.mjs` uses Playwright as external test tooling, with synthetic media;
it is not a Sutegi dependency. Install it into a separate temporary directory:

```sh
npm install --prefix /tmp/sutegi-browser-tests playwright
/tmp/sutegi-browser-tests/node_modules/.bin/playwright install chromium
export PLAYWRIGHT_MODULE=/tmp/sutegi-browser-tests/node_modules/playwright/index.mjs
# Start the example with the same CALL_TOKEN first.
CALL_BASE_URL=http://127.0.0.1:8080 node examples/call/verify.mjs
```

The script verifies rejected credentials/origins, denied unauthenticated WS,
two-way decoded audio/video, reconnect and stale generation fencing, camera
recording/upload, authorized playback/seek, HEAD, 206, 416, and cross-room denial.
It saves a screenshot to `/tmp/sutegi-call-browser.png` (override
`CALL_SCREENSHOT`). Run again with a TURN-configured server and
`EXPECT_RELAY=1`; the test checks the selected ICE candidate pair is relay on
both sides. Consult [coturn's configuration reference](https://github.com/coturn/coturn/blob/master/README.turnserver)
when setting up a local relay. Loopback peers are a development-only setting.
